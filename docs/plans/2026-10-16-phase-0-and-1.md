# autoclaude Phase 0 and Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the five runtime assumptions (Phase 0), then extract the source pipeline into a standalone, compiled `autoclaude` CLI that runs one project's issues to pull requests with Claude Code on Windows, macOS and Linux, at parity with the source and without merging (Phase 1).

**Architecture:** A deterministic Node orchestrator per project ports the source engine (ledger, claims, worktrees, situation, review decision, publish, merge verdict, guard) almost unchanged and replaces the model-run orchestrator skill with code. Every stage — and every review angle and scorer — is a separate headless `claude -p` child process with the worktree as cwd, a rendered prompt file, a dispatch file, a generated fence and no forge credentials. Project facts come only from the project's `.autoclaude/`.

**Tech Stack:** Node ≥ 22, TypeScript (strict, ESM, `tsc` to `dist/`), vitest, prettier, one runtime dependency (`cross-spawn`), `git`, `gh`, Claude Code CLI, Git Bash on Windows.

**Spec:** `docs/specs/2026-10-16-autoclaude-design.md` (this repository). Source code being ported: `C:\Coveniq-ai-app` on `develop`, frozen (`scripts/autodev/`, `.claude/skills/autodev-*/SKILL.md`, `tests/unit/autodev/`). File-by-file port notes and the defect locations: `C:\Coveniq-ai-app\docs\superpowers\specs\2026-10-16-autodev-extraction-to-autoclaude.md` (on branch `docs/autoclaude-extraction` until merged). Read both before Task B1.

## Global Constraints

- Node: `"engines": { "node": ">=22" }`; CI runs Node 24 on `ubuntu-latest`, `macos-latest`, `windows-latest`, and Node 22 on `ubuntu-latest`.
- TypeScript `strict: true`, `module`/`moduleResolution` `NodeNext`, ESM only, compiled with `tsc` to `dist/`; nothing runs through `tsx` at run time (design C6). `bin`: `"autoclaude": "dist/cli/main.js"`.
- Runtime dependencies: `cross-spawn` only. Dev: `typescript`, `vitest`, `@types/node`, `@types/cross-spawn`, `prettier`.
- `.gitattributes`: `* text=auto eol=lf`. Every parser accepts CRLF and a leading UTF-8 BOM.
- English everywhere. No content of any consumer project: no Coveniq code, rules, fixtures, run logs (design anti-goal). Test fixtures are generic.
- Report contracts unchanged: the block markers `AUTODEV-PLAN`/`AUTODEV-PLAN-END`, `AUTODEV-REPORT`/`AUTODEV-REPORT-END`, `AUTODEV-PLAN-REVIEW`…`PLAN-REVIEW-STATUS:`, `AUTODEV-CODE-REVIEW`…`CODE-REVIEW-STATUS:`, their fields, the rule-table grammar, `policy(level, confidence, threshold)`, the label counters `<fixRound><n>`/`<reviewRetry><n>`, and the GitHub comment markers the source writes (claim, release, review comment) keep their exact spelling so archived runs and existing claims stay readable.
- CLI exit codes keep the source meanings: 0 decided/ok, 1 cannot decide or failed, 2 incomplete report or blocking hook, 3 rebase conflict (publish) or no test files (red step), 64 usage error.
- Paths: per project, config in `.autoclaude/`, state in `.autoclaude/state/`, worktrees under `worktrees.root` (default `.autoclaude/worktrees`), reports in `<worktree>/.autoclaude/state/reports/<stage>.md`, plans in `<worktree>/.autoclaude/state/plans/<issue>.md`.
- Every `gh` call carries `-R <owner>/<repo>` resolved from `forge.remote`; every git call uses `forge.remote`, never the literal `origin`.
- Project commands (`bootstrap`, `gates[].check|fix`, `redStep.run|install.run`) run through `bash -c` on every OS; on Windows the bash of Git for Windows.
- Stage processes never fetch, pull, push or call `gh`; the engine fetches before every stage and does every forge write (design C5).
- No text the engine writes to GitHub or into a commit subject carries a CI skip marker (`[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]`, `[actions skip]`).
- Phase 1 behaviour is the source's except: the defects in design § 10, the priority queue order (§ 10, first row), complete listings, engine-written triage labels and comments, and the stage record (pid/instance). Budget, triage schedule, author trust, notifications and auto-merge are later phases; their config keys are accepted and validated but not acted on.

## Review Focus

1. **A project path with a space and a non-ASCII character** (`C:\Users\Jürgen Müller\My Projects\app`, `/Users/jürgen/My Projects/app`) must work for spawn, worktrees and stages. Tests: B2 `round-trips cwd with space and umlaut`, C4 `creates a worktree under a root with a space and umlaut`, E3 `runs a stage whose cwd has a space and umlaut`.
2. **GitHub-controlled text with shell syntax or option-like tokens** (`Fix login & logout --replace $(rm -rf ~) \`id\``) as issue title, reason or comment must never be interpreted. Tests: B2 `passes metacharacters verbatim through a .cmd shim`, C4 `treats a title containing --replace as text`.
3. **A runtime CLI that prints an update notice on stderr, or is logged out,** must not crash parsing or be read as success. Tests: E3 `parses the result despite stderr noise`, E3 `classifies a logged-out CLI as auth`.
4. **A machine that slept or rebooted mid-stage** leaves ledger stages whose pid is dead or now belongs to another process. Tests: G4 `marks a foreign-instance stage resume-needed`, G4 `kills an orphaned stage only when its recorded start time matches`.
5. **Project files saved by a Windows editor** (CRLF, UTF-8 BOM) must load. Tests: B3 `loads config.json with BOM and CRLF`, C2 `parses invariants.md with BOM and CRLF`.

## Notes before starting

- **Machines.** The owner works on Windows. Linux runs happen in WSL2 on the same machine. If no Mac is available, macOS is covered by CI only (the suite, not real `claude -p` runs); say so in the Phase 1 exit record.
- **Codex is not installed** on the owner's machine. Tasks A4 (S2, S3) need it and may run in parallel with Part B; Phase 1 does not wait for them (they gate Phase 3 only).
- **Subscription runs never happen in CI.** Every test uses fake runtime executables; only Part A and Task I3 call the real `claude`.
- **Porting rule.** A port task copies the source module and its tests, applies exactly the listed changes, and keeps everything else. If a listed change makes a source test wrong, the test changes with a comment naming the design section; any other failing source test is a porting bug.
- **"Steps 2–5"** in a task means: run the task's tests and see them fail for the stated reason; implement the listed interfaces; run them and see them pass, together with the whole suite; commit with the given message.

**Interfaces:**

- Produces:
  - `interface RunOptions { cwd?: string; env?: NodeJS.ProcessEnv; input?: string; timeoutMs?: number }`
  - `interface RunResult { status: number | null; signal: NodeJS.Signals | null; stdout: string; stderr: string; timedOut: boolean }`
  - `runSync(cmd: string, args: string[], opts?: RunOptions): RunResult` — `cross-spawn.sync`, never a shell for argv.
  - `run(cmd: string, args: string[], opts?: RunOptions): Promise<RunResult>` — async; on timeout kills the whole tree and resolves with `timedOut: true`.
  - `spawnSupervised(cmd: string, args: string[], opts: RunOptions & { stdoutFile: string; stderrFile: string }): { pid: number; startedAt: string; done: Promise<RunResult>; kill(): Promise<void> }` — output streamed to files (stages can produce megabytes).
  - `bashPath(env?: NodeJS.ProcessEnv): string` — POSIX: `bash`; Windows: `CLAUDE_CODE_GIT_BASH_PATH` if set, else `<git --exec-path>/../../../bin/bash.exe` resolved and checked to exist; throws `Error("Git Bash not found …")` otherwise.
  - `runShell(command: string, opts?: RunOptions): Promise<RunResult>` and `runShellSync(...)` — `[bashPath(), ["-c", command]]`.
  - `shQuote(arg: string): string` — POSIX single-quote quoting for `{files}` substitution.
  - `killTree(pid: number): Promise<void>` — Windows `taskkill /pid <pid> /T /F`; POSIX `process.kill(-pid, "SIGTERM")`, `SIGKILL` after 5 s (children are spawned `detached: true` on POSIX so they lead a group).
  - `processStartTime(pid: number): string | null` — Windows via `powershell -NoProfile -Command "(Get-Process -Id <pid>).StartTime.ToUniversalTime().ToString('o')"`, POSIX via `ps -o lstart= -p <pid>` normalised to ISO; `null` when the process does not exist.
  - `machineStateDir(env = process.env, platform = process.platform, home = os.homedir()): string` — win32 `%LOCALAPPDATA%\autoclaude`, darwin `~/Library/Application Support/autoclaude`, else `${XDG_STATE_HOME:-~/.local/state}/autoclaude`.
  - `samePath(a: string, b: string, platform = process.platform): boolean` — `realpathSync.native` both, then case-insensitive compare on win32 and darwin only (fixes defect 2).
  - `toPosix(p: string): string` — backslashes to slashes.
