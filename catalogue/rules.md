# Rules

The engine's half of the rule catalogue: every rule id a review may cite, and the level
each one carries. A reviewer names the rule and scores its confidence. It never names a
class — the level comes from this table and the class from `policy(level, confidence)` in
`rules.ts`, so the vocabulary cannot drift and no reviewer can escalate its own finding.

`error` above the threshold blocks (`must`). `error` at the threshold and every `warning`
cost a fix round without blocking (`should`). `note` is recorded and deliberately not
fixed now (`later`). Below the threshold a finding is `uncertain`: the observation is
kept, the claim that it is real is withdrawn.

The level belongs to the rule, not to the finding, which is why every `bug/` row is an
error. How sure the reviewer is rides on the confidence instead: a bug whose breaking
input is named and whose line was opened scores 9 or 10 and blocks, while the same rule
recognised as a pattern and not verified scores 7 and costs a fix round.

Every finding quotes the exact source line, or the exact test name, that triggers it, and
the engine looks that line up in the worktree: a finding that cannot quote its line, or
whose quote is not within five lines of where it says, is withdrawn, and the claim that it
is real goes with it.

**The `Evidence` column says which rules that applies to.** A row marked `measurement` is
about what the diff does **not** contain — an acceptance criterion nothing satisfies, a
criterion no task covers, a changed file list against a glob — so it has no line to quote
and the check leaves it alone: withdrawing one would leave the report stating a fact and
the decision seeing nothing. A finding citing a `line` row names its file, its line and
its quote, or it is not a finding. The column is the last one and it is optional; an empty
cell means `line`, which is the answer that keeps the check running.

One exemption is a consistency rule rather than a row's property, and so it is stated here
instead: a `tests/` finding that stands behind what the red step measured — the must the
parser requires under `not-proven`, and the coverage finding under `no-test-files`, which
is reported with the changed paths and no line at all. Those rules quote a line in every
other round, so it is the verdict they stand behind that spares them, not their id.

This file states nothing about any one project. Which paths are fenced, which service may
not be bypassed, which layer owns authorisation — that is the project's half,
`.autoclaude/invariants.md`, in the same grammar. `loadCatalogue()` reads both and refuses an
id stated in both.
